# 首二板回调尾盘推荐说明

> **2026-10 重构说明**：首二板回调已并入 117 尾盘推荐的 `LIMIT_UP` 规则集，不再单独占用
> 14:46 的定时任务。119 负责从涨停池生成推荐池，117 盘中按承接规则过滤。本文档保留原始
> 回测与规则说明。

> 针对「昨日首板/二板的票，次日回调时买入、第三天卖出」这个想法做的尾盘任务。
> 与「涨停首二板_日期」分组不同：那个分组只是把昨日首二板列出来观察；本任务用**分时 K 线**判断回调当日的承接质量，只推企稳的票。

## 一、为什么要用分时

日线回测（2026-05 ~ 10，3056 个回调样本）的结论：

| 回调幅度 | 上涨概率 | 平均收益 |
|---|---|---|
| -2% ~ 0 | 45.0% | -0.16% |
| ≤ -6% | 31.9% | **-1.77%** |

**整体是负期望**，且越跌越差。日线只能看到"收盘跌了多少"，看不到**盘中是怎么跌的**——
同样是 -2%，一路阴跌和急跌后拉回，承接质量完全不同。所以这个任务把判断放到 14:45 的分时上。

## 二、运行链路

```
交易日 16:00   stockLimitUpCollectTask   采集当日涨停（首板/二板）
次日 14:46     stockLimitUpPullbackTask  取昨日首二板 → 抓分时 → 承接筛选 → 生成分组 + 邮件
次日 15:00 前  用户按分组买入
第三日         卖出（-3% 止损按个人纪律执行）
```

RuoYi 调用目标：`stockLimitUpPullbackTask.execute()`，cron `0 46 14 ? * MON-FRI`。

## 三、筛选条件（全部基于 14:45 时点）

| 条件 | 默认值 | 理由 |
|---|---|---|
| 昨日为**首板或二板** | — | 标的来源 |
| 回调幅度 | -4% ~ +1.5% | 回测：深跌（≤-6%）胜率仅 32%，不接飞刀 |
| 分时收盘位置 | ≥ 0.45 | 不在日内最低附近，说明有承接 |
| 现价 vs 分时均价线(VWAP) | ≥ -0.5% | 站上均价线 = 当天买入的人平均不亏，承接有力 |
| 尾盘 30 分钟涨跌 | ≥ -0.5% | 过滤尾盘跳水 |
| 涨停日振幅 | ≤ 12% | 振幅过大说明分歧大 |
| 一字板 | 排除 | 回测：一字板次日回调后表现最差（-1.93%） |
| 流通市值 | ≥ 30 亿 | 微盘（<30 亿）次日平均 -1.00% |
| 换手率 | 3% ~ 20% | 太低没流动性，太高是接盘 |

通过后按承接评分排序（收盘位置 30% + VWAP 25% + 回调适中 20% + 尾盘 15% + 换手 10%），取前 `top-n`（默认 10）。

## 四、输出

- 分组：`首二板回调_日期`，备注记录涨停日与全部阈值；
- 邮件：主题「首二板回调 日期」，正文含回调幅度、收盘位、VWAP 偏离、换手；
- 日志：逐只输出评分与分项指标，并打印过滤分布（哪条挡得最多）。

## 五、已知局限

1. **没有历史分时数据**，这个任务无法回测，只能先跑起来积累实盘样本；
2. 14:45 的价格与收盘价有差异，尾盘 15 分钟的走势没有纳入；
3. 承接评分权重是启发式，跑 1~2 个月后按实际胜率再调；
4. 不构成买入建议，仓位与止损仍需自己控制。

## 六、配置

```yaml
stock:
  limit-up-pullback:
    group-name: 首二板回调
    top-n: 10
    min-pullback: -4.0
    max-pullback: 1.5
    min-close-pos: 0.45
    min-vwap-dev: -0.5
    min-tail-change: -0.5
    max-limit-up-amplitude: 12.0
    exclude-one-line: true
    min-cap-yi: 30
    min-turnover-rate: 3.0
    max-turnover-rate: 20.0
```
