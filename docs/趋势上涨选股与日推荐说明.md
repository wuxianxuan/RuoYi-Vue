# 趋势上涨选股 + 日推荐 说明文档

> 本文档存档两个定时任务的最终设计、配置、逻辑与回测结论，供后续迭代参考。

## 一、两个任务的分工

```
交易日 16:40  stockRisingTrendTask（趋势上涨选股，波段状态机）
                ↓ 对每只股票跑波段状态机（进池 → 上升/震荡/回调 → 删除）
        全量覆盖「趋势上涨选股」积累分组 + 写入 stock_rising_state 表
                ↓
交易日 16:50  stockDayTradingTask（日推荐）
                ↓ 读积累分组 + stock_rising_state 波段状态
        ① 按状态拆组：上升组 / 震荡组（回调股不进推荐）
        ② 换手率 < 3% → 不进当日推荐（但留池）
                ↓
        生成「趋势上涨选股_日期_上升」和「趋势上涨选股_日期_震荡」两个日推荐分组
                ↓ 另：遍历当日涨停记录
        ③ 过滤首板/二板（up_num 空=首板，「N天2板」=二板）
                ↓
        生成「涨停首二板_日期」分组
```

**核心分工**：积累池负责「撒网早期捕获趋势 + 波段跟踪破位删除」（广度），日推荐负责「按波段状态拆分 + 换手率精选」（精度）。

## 二、最终配置（application.yml）

```yaml
stock:
  rising-trend:             # 进池判定 + 波段跟踪
    lookback-days: 120      # 回看日历天数（含 MA20/ATR20 预热期）
    entry-window: 5         # 进池窗口 N 日
    min-gain: 5.0           # 进池区间涨幅≥5%
    limit-up-threshold: 9.8 # 涨停判定阈值（进池时过滤涨停脉冲）
    ma-period: 20           # 进池要求收盘 > MA20（拦超跌反弹）
    atr-period: 20          # ATR 周期
    shake-atr: 1.0          # 回撤 ≤1ATR → 震荡
    delete-atr: 2.0         # 回撤 >2ATR → 删除（移出池）
    reentry-cooldown-days: 10  # 删除后冷却交易日数，避免反复「删除-重进」
    exclude-st: true        # 排除 ST
    markets: SH,SZ          # 扫描市场
    exclude-code-prefixes: 300,301,688,689  # 排除创业/科创
    group-name: 趋势上涨选股
  day-trading:              # 日推荐
    min-turnover-rate: 3.0      # 换手率≥3% 才进日推荐
    top-n: 15                   # 每组按评分只取前 N 只
    limit-up-group-name: 涨停首二板  # 涨停首二板分组名（固定名，不含日期）
```

## 三、stockRisingTrendTask 波段状态机逻辑

对每只股票，从回看锚点起逐根日K线跑状态机：

**进池条件（未入池时，看最近 N=5 根日K）**：
1. 指标周期已够（至少 MA20 / ATR20 所需根数，避免次新股拿 MA5 当 MA20）。
2. 窗口内无涨停（单日涨幅 ≥ 9.8%）。
3. 区间涨幅 (最高-最低)/最低 ≥ 5%。
4. 当前收盘创 5 日新高。
5. 当前收盘 > MA20（中期趋势约束，拦截跌深后的超跌反弹）。

**入池后每日状态迁移（回撤用 ATR 归一化）**：
- 创新高 → 状态=上升，抬高阶段高点；若此前是「回调」则把回调谷记为新阶段低点（低点抬高）。
- 未创新高 → 回撤 = (阶段最高 - 当前收盘) / ATR20：
  - `> 2×ATR` → **删除**（移出池），并记录删除日；
  - `≤ 1×ATR` → 震荡；
  - `1~2×ATR` → 回调。
- 删除后进入 **冷却期 10 个交易日**，期间即使满足进池条件也不重新入池（避免同一波段反复「删除-重进」）。

**止损价**：每次重算对池内股票写入 `stock_rising_state.stop_price` = `max(阶段低点, 阶段高点 - 2×ATR)`，
即「跌破阶段低点」或「回撤超过 2ATR」任一成立即视为波段结束，可直接作为持仓止损参考。

**每日全量重算**：从截止日往前回看 120 日历日（约 80 个交易日，其中前 20 根用于 MA20/ATR20 预热），从头跑状态机取当日终态，幂等、无状态污染，漏跑/重跑不影响结果。

**命中后**：全量覆盖「趋势上涨选股」分组（含删除），并把每只池内股票的波段状态（status/high/low/enter）写入 `stock_rising_state` 表。

**支持日期入参**：`stockRisingTrendTask.execute(日期)`，为空默认当天。

## 四、stockDayTradingTask 日推荐逻辑

1. 读「趋势上涨选股」分组内股票（已被 rising-trend 维护好，破位股已移出），及每只股票的波段状态（stock_rising_state）。
2. 逐只判定：
   - **按状态拆组**：波段状态=上升 → 上升组；=震荡 → 震荡组；=回调 → 不进推荐（回撤已 1~2ATR，等企稳）。
   - **流动性**：换手率 < 3% → 不进当日推荐（但留池）。
   - **评分排序**：通过上面两刀的股票按 0~1 评分降序，每组只取前 `top-n`（默认 15）只：
     阶段位置 55%（现价在阶段低点与阶段高点之间的相对位置）+ 量能 20%（量比/2，封顶 1）
     + 换手适中 15%（越接近 6% 越高）+ 当日涨幅适中 10%（越接近 3% 越高，避免追高）。
3. 生成「趋势上涨选股_日期_上升」和「趋势上涨选股_日期_震荡」两个日推荐分组（幂等，同名已存在则跳过）。
   日志逐只输出评分、现价与止损价（`stock_rising_state.stop_price`），分组备注记录「命中多少只、取前多少只」。

**另——涨停首二板分组**：

1. 查询当日涨停记录（`stock_limit_up_record`，按 trade_date）。
2. 解析 `up_num` 得到连板数：空=首板(1)，「N天M板」取末尾 M；只留首板(1)和二板(2)。
3. 按股票代码去重（同一股票跨板块可能多条），生成「涨停首二板_日期」分组（幂等）。

**支持日期入参**：`stockDayTradingTask.execute(日期)`，为空默认当天。

## 五、关键设计结论（为什么这么设计）

1. **回撤用 ATR 归一化，不用「回撤/涨幅」比值**：固定比值（如回撤≤20%）会让绝对容差随涨幅缩放，小涨幅时震荡带过窄、大涨幅时删除过迟，且无法做阶段性判断。ATR 归一化后阈值稳定（震荡≤1ATR、删除>2ATR），可逐日做阶段判定。
2. **进池加「收盘 > MA20」拦超跌反弹**：跌深后的小反弹（如克来机电 10-20 从 -27% 跌深后 +5.4% 反弹）在局部 5 日形态上与真趋势起点无法区分，但真趋势必然站上中期均线、超跌反弹必在均线下方。这一条是区分两者的关键。
3. **删除逻辑移进 rising-trend**：破位删除（>2ATR）由 rising-trend 每日全量重算完成，day-trading 不再做「走下坡」减法，职责更清晰。
4. **每日全量重算而非增量状态机**：算法对 K 线历史确定，全量重算幂等、天然容错（漏跑/重跑/改参数后重跑都一致），避免增量状态机的脏状态与迁移成本。
5. **去掉 isRecentWeak，直接用波段状态做趋势过滤**：原「最近走弱」过滤（近两日连跌 / 跌破前天开盘）是波段状态机的「前身」临时方案。有波段状态后它已冗余甚至矛盾——回测显示它对「上升」组几乎无影响（挡 1 只），却挡掉「震荡」组 54% 的股票（震荡本就是浅回撤，正是要推的买点）。故日推荐改按波段状态拆组，删掉 isRecentWeak。
6. **积累池宽松、日推荐严格**：进池门槛低保证早期捕获；日推荐按波段状态拆组 + 换手率过滤保证精度。

## 七、调参指南

| 参数 | 含义 | 调大 | 调小 |
|---|---|---|---|
| min-gain | 进池区间涨幅门槛 | 池子更净、发现更晚 | 池子更宽、发现更早 |
| entry-window | 进池窗口天数 | 更稳（需更长上涨） | 更敏感 |
| ma-period | 进池均线周期 | 更严格（更长趋势） | 更宽松 |
| shake-atr | 震荡阈值(ATR) | 震荡带更宽 | 震荡带更窄 |
| delete-atr | 删除阈值(ATR) | 容忍更深回撤、池更大 | 更快止损、池更小 |
| reentry-cooldown-days | 删除后重新进池的冷却天数 | 池子更干净、少反复 | 更快重新捕捉 |
| min-turnover-rate | 日推荐换手率门槛 | 日推荐更少更精 | 日推荐更多 |
| top-n | 每组日推荐输出上限 | 候选更多、更难决策 | 更聚焦（建议 10~15） |
